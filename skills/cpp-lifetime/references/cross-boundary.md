# 跨边界合同

只检查本次数据经过的边界；以下不是每次修改都必须执行的清单。

## 共享内存

- 共享地址空间中的 offset/handle 与进程内指针分开表达；验证映射标识、布局版本、偏移、长度、对齐与整数溢出。
- 跨进程表示不要默认包含 `std::string`、进程内 `shared_ptr` 或普通 STL 容器。allocator、对象布局、ABI 与同步原语必须有明确的进程共享合同。
- 不能仅凭类型是 `std::atomic` 就推定目标平台支持进程间同步；确认平台、构造方式与原语承诺。
- generation/epoch 用于区分重用或重启前后的身份；检查 identity 后还要保证使用期间无法释放/替换。单次比较不能消除 check-then-use 竞争。
- lease/read guard/refcount/epoch reclamation 分别按项目协议证明作用；不要混淆“句柄有效”和“底层页在整个读取期间存活”。
- 读取失败、短读、校验错误应按接口合同返回。只有调用方明确支持部分结果时才能返回前缀；否则维持完整性或走已有的可观测恢复路径。

## 网络与设备 I/O

描述实际字节路径，包括源 owner、打包/转换、staging、注册、提交、传输、目标写入、完成回调与释放。不把有 host staging 的路径称作已经证明的零拷贝。

区分“提交成功”“本地发送完成”“远端可见”“应用已消费”。使用相应协议的真实完成保证，不推定某个 ACK 同时满足全部条件。

登记与 allocation、页、adapter/context 和 generation 的绑定范围要明确。注销/回收必须晚于所有实际使用；失败重试也需要持有对应 generation 的资源。

不同设备队列/stream 之间使用 API 承诺的依赖或事件。避免不必要的 host wait，但保留保证正确性的排序；移除等待必须指出替代依赖。

## 重启与回收

检查 producer/consumer 各自崩溃时可能留下的状态：过期句柄、未 ACK 请求、已释放的登记、在途写入、未归还额度。依据现有恢复协议处理，不凭空加第二套状态机。

有关“安全”的结论要区分源码合同、可控故障测试与真实硬件证据。没有对应环境时把该项留为未验证，继续完成其他可验证工作。
