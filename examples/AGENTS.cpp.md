# C++ 项目接入示例

供维护者选择后合并到已有 `AGENTS.md`；不是一个应整文件覆盖项目配置的模板。先检查项目事实，再写入具体构建 target、错误类型和命名规则。

## 可以采用的共同约定

- C++ 修改遵循本仓库已有的语言标准、错误传播、命名和格式化配置。
- 日常编码可使用 `cpp-core`；生命周期/并发、精简、评审、验证、性能任务按需选择对应 `cpp-*` 技能，不一次加载全部。
- 删除检查时，说明哪一处校验/类型/不变量使其冗余，以及该保证为何没有在异步、并发或跨进程边界失效。
- 新增抽象时说明实际职责。单次使用的 RAII 可以有价值；纯转发层需要业务、寿命、隔离或稳定接口等理由。
- 内容、长度、顺序和精度合同不能为了通过测试而截短、吞错或放宽。只有需求本身改变时才修改合同和相应测试。
- 评审堆叠分支时使用当前 PR/MR 的实际 base，并明确是否包含本地修改。
- 性能报告区分源码推断、当前测试、真实硬件测量与尚未验证的范围。

## 项目中需要维护的事实

在现有文档中确认或补充实际的：

- 构建入口、相关 target、测试运行方式和必要 CI 检查。
- 编译器与 C++ 标准、异常/RTTI、Status/Result 或其他错误策略。
- 所有权和共享内存/网络/设备完成合同所在文档。
- 格式化与静态检查的版本、配置和作用范围。

这些事实属于项目，不应复制为技能合集里的全局默认值。
