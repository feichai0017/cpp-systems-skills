# C++ 代码精简

以减少需要维护的职责和状态为目标；行数只是结果。先确认本次目标与改动范围，遵循项目命名、错误处理、格式化和兼容合同。

## 先固定范围与行为

- 确认用户指定的文件、提交、PR/MR 或基线。堆叠分支用当前 PR/MR 的实际 base；不要默认 `main`。
- 分别看已提交、暂存、未暂存和未跟踪的相关代码。只有用户指定仅审某层时才限制到该层。不要因 staged 非空忽略其他改动。
- 读调用方、合同与相关测试，记录需要保持的结果、错误、资源释放和并发语义。不要把已有问题或其他人的编辑混入清理。

## 删除之前给出理由

| 候选项 | 可删除的证据 | 必须保留的职责 |
| --- | --- | --- |
| 重复校验 | 指出上游建立保证的位置、同一对象及保证持续有效的范围 | 不可信输入、可变别名、异步状态变化、跨进程重新校验 |
| `try/catch` | 只有原样重抛/重复日志，且没有转换、补偿或清理职责 | API 异常边界、错误映射、恢复、事务回滚 |
| helper / wrapper | 没有业务语义、寿命管理、隔离、接口稳定或真实复用 | 一次使用但建立不变量/RAII 的对象 |
| factory/provider/manager | 只包住直接构造或转发，没有状态和策略职责 | 受约束构造、资源池、真实多实现选择 |
| 接口、多后端、开关 | 只有一个实现，也没有测试替身或平台差异等替换需求 | 已有的多个实现、插件或 ABI 边界 |
| 同一事实的多个条件 | 一个条件已由数据结构的不变量蕴含（计数大于零说明子元素存在） | 不变量不成立的输入确实会到达这里 |
| 项目同类接口不做的参数检查（判空、下标范围） | 已有接口不检查同样的参数，前提已写进注释 | 项目在同类接口上检查；参数直接来自不可信输入 |
| 先校验再解析 | 解析函数的结束位置和错误码已能判断合法性 | 解析前必须拒绝的输入，如长度上限 |
| 与项目已有工具重复的辅助代码 | 指出已有实现的位置，并确认边界条件一致 | 已有实现语义不同，如空白定义、编码或错误处理 |
| 只有一个实例化的模板、SFINAE 链、递归元函数 | 只有一个实际类型，或 `if constexpr`、concept、`constexpr` 函数可以表达同样的选择 | 公开的泛型 API、已有多个实例化 |
| 处理不会出现的情况的分支和参数 | 查过调用方和输入来源，该情况不会产生 | 外部输入、跨进程数据、文档承诺的行为 |
| 手写的标准库已有运算（最大公约数、分数约分、类型范围、单位换算） | 当前标准库提供相同语义（`std::gcd`、`<ratio>`、`std::numeric_limits`、`<chrono>`） | 项目标准下不可用，或语义不同（如比例只在运行时可知） |
| 为新功能另写的更严格或更宽松的解析，或为新功能修改的共用函数 | 已有函数的接受范围就是合同要求 | 合同明确要求不同的语法，或修复的是本次合同依赖的缺陷 |
| 分支/状态 | 从可定位的不变量可证明不可达，且取消、重试、重启不改变该结论 | 额度、去重、generation、ACK、完成与回收协议 |
| 注释/日志 | 复述语法、重复同一事件、没有诊断用途 | 所有权、协议原因、故障定位和操作所需事件 |

对于每个被删除的检查，能够补全：

> 保证在 `<类型或函数位置>` 建立；检查针对同一份 `<对象/快照>`；到本次使用前，`<同步/不可变性/owner>` 保证它不失效。

无法补全时先查证，保留检查或收敛到正确边界。不得把“调用方应该保证”“正常情况下不会发生”当作证明。

## 合并而不抹平差异

- 共享纯计算或窗口选择时，保留不同路径各自的验证、ownership 与完成语义。
- 合并重复状态前，确认它们是同一事实，而非不同阶段的观测值、缓存版本或已确认状态。
- 直接调用足够时删除纯转发层；需要稳定 API、线程切换、语义转换或资源持有时保留明确边界。
- 替换自定义工具前先查仓库与已引入库，核对实际版本和行为合同。复用后不要默认再建立一层只有转发作用的适配器。
- 手写代码与项目标准和库范围内的标准设施语义完全相同时，用标准设施替代以减少维护代码：手写特殊成员换成 `= default` 或 Rule of Zero，erase-remove 换成 `std::erase_if`（C++20），手写交换和置空换成 `std::exchange`，手写查找循环换成算法。先核对边界条件、异常与迭代器失效行为一致；不为替换而升级标准，也不在关闭 STL 的代码中引入标准库。
- 已有容器或智能指针包装可能提供空值/边界检查及构建策略。检查实现与编译条件后判断职责；不因接口相似而删掉安全层，也不把输入错误改成 Release 中可能消失的断言。
- 不增加静默 fallback、兼容 shim 或新开关来回避合同问题。任务确实要求兼容时，明确适用范围、可观测行为和维护责任。
- 保留清晰的控制流，不用复杂表达式、宏或过度模板化换取短代码。
- 本次范围内带 `ensure`、`try`、`maybe`、`safe`、`checked`、`do`、`handle`、`process` 等前缀或重复作用域上下文的名称，按实际行为重命名并同步调用方；不扩大到范围之外。

## 收尾

验证保持不变的行为，以及本次触及的生命周期、错误和竞争路径。格式化只覆盖必要范围；不批量压制诊断或改仓库风格配置。

交付说明最有价值的删除、它为何安全、实际验证，以及有意保留的关键保护。若没有足够证据支持精简，直接说明；不要为了展示成果制造修改。
