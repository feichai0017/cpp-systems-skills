# 测试策略

为系统代码设计测试、选择测试替身、测试并发与故障路径，或引入模糊测试时阅读。沿用项目已有的测试框架与目录约定。

## 分层

| 层次 | 覆盖内容 | 特点 |
| --- | --- | --- |
| 单元测试 | 纯逻辑：编解码、状态机、计算 | 快速、确定，不碰真实 I/O |
| 组件测试 | 一个模块与它的真实依赖（临时目录中的文件、本地 socket） | 验证与操作系统的真实交互 |
| 集成/端到端 | 多进程、真实设备、真实网络 | 慢，覆盖部署形态；按触发条件运行 |

每个测试只断言外部可观察的行为或明确的不变量，不断言私有实现细节。

## 测试替身

- 优先用 fake：内存中的文件系统、可手动推进的时钟、记录请求的假服务端。fake 实现完整但简化的行为，测试读起来像真实场景。
- 只有在“调用了什么、以什么顺序”本身就是合同时才用 mock（gMock），例如“失败时必须调用回滚”。过多的 mock 会把实现细节固定在测试里。
- 时钟、随机数、文件系统、网络这些依赖通过构造函数注入，才能在测试中替换（见 `cpp-core` 技能的设计范式）。不要为测试在产品代码中加入全局开关。

## 确定的并发测试

- 用 `std::latch`/`std::barrier`、手动驱动的执行器或可控的同步点，把关键交错固定下来：例如“取消发生在提交之后、完成之前”。
- 不依赖 `sleep` 制造时序；需要超时的测试使用可推进的假时钟。
- 并发测试在 TSan 构建中运行。压力测试作为补充，固定随机种子并在失败时打印种子。

## 故障注入

- 系统调用失败：通过可注入的接口（构造函数注入的 I/O 层）或测试专用的包装函数，模拟 `EINTR`、短读写、`ENOSPC`、`EIO`。
- 失败点（failpoint）：在关键位置放置可在测试中激活的注入点（类似 RocksDB 的 SyncPoint），用于测试崩溃恢复和竞态；产品构建中编译为空。
- 进程级故障：在写入、`fsync`、`rename` 之间强制终止进程（`kill -9`），重启后验证恢复结果。
- 网络故障：丢包、延迟、连接重置，可以用本地代理或 Linux 的 `tc netem`。

## 模糊测试

解析器、协议解码、文件格式读取和任何处理不可信输入的代码都应有模糊测试：

```cpp
#include <cstddef>
#include <cstdint>
#include <span>

#include "protocol/frame.h"

extern "C" int LLVMFuzzerTestOneInput(const std::uint8_t* data, std::size_t size) {
  const auto bytes = std::as_bytes(std::span(data, size));
  (void)protocol::DecodeFrame(bytes);   // 只要不崩溃、不触发 sanitizer 即通过
  return 0;
}
```

```sh
clang++ -std=c++20 -g -O1 -fsanitize=fuzzer,address,undefined fuzz_frame.cc frame.cc -o fuzz_frame
./fuzz_frame corpus/ -max_total_time=300
```

- 把发现的崩溃输入加入回归测试与语料库。
- 往返类不变量（编码后再解码得到原值）可以在模糊测试或属性测试（rapidcheck）中检查。

## 其他技术

- 黄金文件测试：磁盘格式和协议的编码结果与提交到仓库的样本逐字节比较，检测格式的意外变化。
- 死亡测试（`EXPECT_DEATH`）：验证不变量被破坏时确实终止，并输出预期信息。
- 多进程测试：共享内存、文件锁、进程间协议需要真正的多个进程，单进程中的线程模拟不能替代。

## Sanitizer 矩阵

| 构建 | 发现的问题 | 注意 |
| --- | --- | --- |
| ASan + UBSan | 越界、use-after-free、泄漏、未定义行为 | 可以合并在一个构建中 |
| TSan | 数据竞争 | 单独构建；与 ASan 不兼容 |
| MSan（仅 Clang） | 读取未初始化内存 | 所有依赖（包括标准库）都要插桩，否则误报很多 |
| compute-sanitizer | CUDA 越界、竞争、未初始化、同步错误 | 运行在 GPU 环境中 |

CI 中至少运行 ASan+UBSan 与 TSan 两种构建的测试。

## 不稳定的测试

- 不稳定的测试说明有竞争、对时序的假设或外部依赖。找到原因并修复；暂时隔离时记录问题和负责人，不用自动重试掩盖。
- 覆盖率（llvm-cov、gcov）用来发现完全没有被测试的路径，不作为追求的目标数字。
