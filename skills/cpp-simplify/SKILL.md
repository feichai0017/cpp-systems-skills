# C++ 代码精简

以减少需要维护的职责和状态为目标；行数只是结果。先确认本次目标与改动范围，遵循项目命名、错误处理、格式化和兼容合同。

## 先固定范围与行为

- 确认用户指定的文件、提交、PR/MR 或基线。堆叠分支用当前 PR/MR 的实际 base；不要默认 `main`。
- 分别看已提交、暂存、未暂存和未跟踪的相关代码。只有用户指定仅审某层时才限制到该层。不要因 staged 非空忽略其他改动。
- 读调用方、合同与相关测试，记录需要保持的结果、错误、资源释放和并发语义。不要把已有问题或其他人的编辑混入清理。

## 删除之前给出理由

| 候选项 | 可删除的证据 | 必须保留的职责 |
| --- | --- | --- |
| 重复校验 | 指出上游建立保证的位置、同一对象及保证持续有效的范围 | 不可信输入、可变别名、异步状态变化、跨进程重新校验 |
| `try/catch` | 只有原样重抛/重复日志，且没有转换、补偿或清理职责 | API 异常边界、错误映射、恢复、事务回滚 |
| helper / wrapper | 没有业务语义、寿命管理、隔离、接口稳定或真实复用 | 一次使用但建立不变量/RAII 的对象 |
| factory/provider/manager | 只包住直接构造或转发，没有状态和策略职责 | 受约束构造、资源池、真实多实现选择 |
| 分支/状态 | 从可定位的不变量可证明不可达，且取消、重试、重启不改变该结论 | 额度、去重、generation、ACK、完成与回收协议 |
| 注释/日志 | 复述语法、重复同一事件、没有诊断用途 | 所有权、协议原因、故障定位和操作所需事件 |

对于每个被删除的检查，能够补全：

> 保证在 `<类型或函数位置>` 建立；检查针对同一份 `<对象/快照>`；到本次使用前，`<同步/不可变性/owner>` 保证它不失效。

无法补全时先查证，保留检查或收敛到正确边界。不得把“调用方应该保证”“正常情况下不会发生”当作证明。

## 合并而不抹平差异

- 共享纯计算或窗口选择时，保留不同路径各自的验证、ownership 与完成语义。
- 合并重复状态前，确认它们是同一事实，而非不同阶段的观测值、缓存版本或已确认状态。
- 直接调用足够时删除纯转发层；需要稳定 API、线程切换、语义转换或资源持有时保留明确边界。
- 不增加静默 fallback、兼容 shim 或新开关来回避合同问题。任务确实要求兼容时，明确适用范围、可观测行为和维护责任。
- 保留清晰的控制流，不用复杂表达式、宏或过度模板化换取短代码。

## 收尾

验证保持不变的行为，以及本次触及的生命周期、错误和竞争路径。格式化只覆盖必要范围；不批量压制诊断或改仓库风格配置。

交付说明最有价值的删除、它为何安全、实际验证，以及有意保留的关键保护。若没有足够证据支持精简，直接说明；不要为了展示成果制造修改。
