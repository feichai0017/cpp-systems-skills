# C/C++ 日常编码

日常写 C 和 C++ 时默认使用本技能，无需用户点名：在项目标准内完成最小必要实现，复用已有代码，沿用项目写法，准确命名，保持业务行为、所有权和错误/并发合同。专项技能只在任务确实涉及其职责时补充；不为小修改制造设计文档或全套审计。

## 先确定项目事实

- 读取 `AGENTS.md`、相关接口与调用方、构建入口和最近邻测试。用户要求与项目约定优先于本技能的默认建议。
- 从构建文件或实际编译命令确认语言标准、编译器、构建系统、异常/RTTI 策略、错误类型、命名和格式化配置，不猜测、不升级。README、构建选项和配置宏规定的库范围与移植约束（关闭 STL、同一源文件按 C 编译、不依赖异常、停留在 C++98/03）优先于下文的现代写法。
- 用一句话说明要改变的行为及验收条件。缺失信息会改变兼容性、所有权或外部行为时再澄清，其他情况按已有约定推进。
- 范围按行为合同确定，任务点名的函数、输入或报错只是例子。找出承担同一合同的同族函数、重载、调用路径和其他语言的包装，一起修复，或在报告中说明为什么不改。包装把结果转成更窄的类型、换了单位或默认值时，按包装后的类型重新检查范围和失败条件。“最小必要实现”指不做合同之外的改动，不是只改点名的例子。

## 先复用

- 写辅助函数、循环或检查之前，在同一文件、同一模块、项目公共工具和当前标准库里查找做同一件事的代码，找到就直接调用。标准库的算法和编译期运算（`<algorithm>`、`<numeric>`、`<ratio>`、`<chrono>`、`<limits>`）同样不手写：运行时才知道的选择（单位、格式、类型标签）只在一处分派，每个分支用编译期参数调用同一个模板，比例、约分和范围交给 `std::ratio_divide`、`std::numeric_limits`。
- 调用已有函数前读它的前置条件：断言、注释和函数开头的检查（是否以 NUL 结尾、长度的单位、谁持有内存、返回值的含义），照附近调用方的方式准备参数。这些条件不必再检查一遍，但必须满足。
- 复用已有的解析、转换或校验时沿用它的接受范围，不为新功能另写更严或更松的版本，也不为新功能修改共用函数。认为已有行为有缺陷时在报告中指出；只有本次合同依赖的缺陷才一并修复，并写明。
- 新增通用组件时按“仓库已有实现 → 已引入依赖和标准库 → 合适的新依赖 → 参考相似实现 → 自行实现缺失部分”查找，比较语义、所有权、线程模型和维护成本；普通修复先查本地，不强制上网或生成选型报告，见 [复用与源码参考](references/reuse-and-precedents.md)。

## 只写合同需要的代码

- 只处理合同和真实调用方会产生的情况。某种输入、平台、并发或故障会不会出现，从项目说明、调用方和输入来源确认；确认不了时不先写处理代码。防护机制同样如此：唯一的临时文件名、重试循环、锁、去重和回滚，只在项目说明或调用方显示存在对应情况（多个写入者、可重试的瞬时错误）时才加。非法输入按项目的错误方式统一拒绝，不为每种非法形式各写一段处理。标准库设施自身的限制是可以接受的边界，例如比例运算溢出时 `<ratio>` 编译失败，不为没有调用方的极端类型改写实现。
- 只有一条实现路径时直接实现：不引入接口或虚函数、策略/工厂/注册表、多个后端、开关或额外的模板参数；出现第二个实现或真实的替换需求（测试替身、平台差异）时再抽象。不保留不会执行的 fallback 分支。
- 新函数或类型要承担职责：业务语义、不变量、资源所有权、真实复用或隔离。只包一次调用、只判断一个条件的函数和纯转发层直接写在调用处；包装层若承载边界检查、错误语义或平台策略，就有职责，不因接口相似而删除。
- 控制流直观，适合时提前返回减少嵌套，不用复杂表达式、宏或压缩行数换取简短。合并重复状态前确认它们表达同一事实，不混淆不同阶段、版本或已确认状态。清理本次改动造成的无用代码，不顺带清理无关代码。
- 不为测试改动产品代码：不加测试专用的钩子、全局开关、重定义的分配器宏或只在测试中走的分支，用测试宏包起来也不行。失败路径用项目已有的替换点（可替换的分配器头文件、注入的依赖、已有的 failpoint）或测试文件里的替身来测；没有替换点时不新建，在报告中写明哪些路径没有测试。

## 沿用项目写法

- 新代码与相邻实现一致：错误处理、日志、断言、容器、字符串和资源释放用项目已有的方式和类型。项目有资源 owner 类型就用它；项目显式释放（例如返回错误的 `Close`）时，把函数内的释放整理到一处（串联错误、合并出口），不为单个函数新建 owner 类型；多个函数需要同样的释放、或释放点无法收拢时，才新增 owner。
- 新增接口对照同类接口的整组写法：重载集合（如 `const char*` 与 `std::string`、const 与非 const）、命名、文档注释和测试位置。新增或改变公开能力时，更新项目文档中列出同类能力的地方（README、API 文档、CHANGELOG）；项目没有这类文档时不新建。
- 不改动与合同无关的已有行，包括文件编码、字符转义和换行；格式化限于受影响的范围。
- 注释写不变量、协议约束、所有权和非直观原因，不复述代码。
- 头文件自包含，只放调用方需要的声明；新文件放在正确的模块层级并加入构建目标，如实区分公开与私有依赖，不靠间接依赖碰巧通过编译。第三方依赖沿用项目已有来源并固定版本。见 [项目结构](references/project-layout.md)、[CMake](references/build-cmake.md)、[Blade](references/build-blade.md)。

## 现代 C++ 写法

纯 C 项目按项目的 C 标准和写法编写，本节不适用。C++ 项目在已确定的标准和库范围内用足它允许的设施，不升级标准，也不写低于该标准的旧式代码；项目已有等价类型（`Status`、`Result`、span、日志与断言宏）时用项目类型；没有约束的新项目以 C++20 为基线。下列默认值以 C++11 及以上且可用标准库为前提；受限的代码和各项写法见 [现代 C++ 写法](references/modern-idioms.md)。

- **所有权**：不写裸 `new`/`delete`/`malloc`；独占用 `std::make_unique`，确需共同决定销毁才用 `std::make_shared`；包装 C 句柄用 `std::unique_ptr` 加删除器 struct。优先 Rule of Zero；自定义 owner 时同时决定复制、移动与析构，移动操作 `noexcept`。单参数构造函数 `explicit`，覆盖虚函数写 `override`/`final`。
- **接口**：只读字符串用 `std::string_view`，只读序列用 `std::span` 或项目等价类型；要保存的参数按值接收再 `std::move`；结果通过返回值传递；返回 `Status`/`Result` 的函数标 `[[nodiscard]]`。
- **错误与类型**：可失败操作返回项目的 `Status`/`Result`（C++23 可用 `std::expected`），`std::optional` 只表示合法缺席；文本转数字用 `std::from_chars`；用 `enum class`、`nullptr`、`constexpr`、`static_cast`/`std::bit_cast`、`std::chrono`、`std::byte`。
- **控制流与泛型**：range-for、结构化绑定、`<algorithm>` 与 ranges；C++17 用 `if constexpr` 取代标签分派，C++20 用 concepts 约束模板。至少两个实际类型共享同一合同时才写模板，见 [泛型与模板元编程](references/generic-programming.md)。
- **并发**：RAII 锁，条件变量带谓词等待，C++20 用 `std::jthread` 与 `std::stop_token`；不用 `volatile` 或 `sleep` 做同步。
- **不写**：头文件中的 `using namespace`、`std::endl`、`NULL`、`typedef`、`return std::move(local)`、对 `const` 对象 `std::move`、`std::bind`、吞错的 `catch (...)`。

## 所有权与类型

- 接口能看出谁持有资源、谁借用、借用到何时结束。引用、指针、`span`、`string_view` 不延长寿命；异步保存借用前证明 owner 的存活期。
- 用已有类型、`enum class`、具名结果或受约束构造表达不变量；只有单位混淆、非法组合或状态转移确有风险时才新增包装类型。`class` 维护共同成立的不变量，`struct` 描述独立字段。
- 不用默认构造的半有效对象隐藏失败；协议必须两阶段初始化时显式表示状态。模板、无异常、C ABI、自定义 allocator 等场景服从项目约束，把必要的底层操作收敛到可审计的边界。设计新类型或模块边界时见 [设计范式](references/design-paradigms.md)。

## 错误与检查

- 沿用项目的 `Status`/`Result`/异常策略，不并行引入第二套错误框架。断言表达程序内部错误，不代替输入校验或错误传播；`optional` 不吞掉解析失败、超时或短读的原因；保留项目区分的 not-found 与 error。
- 保留可操作的错误上下文，不在每层重复记录同一错误；只在恢复、语义转换或终止边界捕获异常；析构不抛出，需要反馈关闭失败时提供显式关闭操作。长度、偏移和容量检查溢出与符号转换；精度或数量不一致时修复合同，不截短结果、放宽阈值或吞错。

每个检查只做一次：

- 每个前提只在建立它的边界检查一次。内部调用链已经保证的条件（参数非空、长度已校验、上一步已成功）不再检查，内部不变量用项目断言表达；不新增只包一个条件的保护函数（`CheckX`、`EnsureY`）。
- 同一事实只用一个条件判断：数据结构的不变量已经说明的情况（计数大于零已说明后面有子元素，迭代器不等于 `end()` 已说明可以解引用）不再用下标、总数或范围确认；错误码已经说明成败时，不再检查句柄或输出值。
- 沿用项目的信任边界：项目已有接口不检查的参数（指针非空、下标范围、数量），新接口也不检查，把前提写进注释；参数来自不可信的外部输入时，在接收输入的那一层检查一次。
- 一个输入只解析一次：用解析函数的结束位置和错误码判断是否合法，不先手写语法校验再调用库函数，也不在解析成功后重复确认。
- 删除已有检查时指出建立保证的类型或代码位置，并确认 Release 配置以及异步、并发、RPC、共享内存下保证仍然有效。

## 语义命名

- 名称结合接口与调用方审查，格式检查通过不代表语义准确。同一概念用同一名称；区分动作与查询、字节与元素、大小与容量、发起与完成：返回量化模式的函数叫 `GetQuantizationMode()`，不叫 `Quantize()`；`Close`、`Stop`、`Flush` 的合同写明实际完成点。
- 函数名直接说明做什么，不加 `ensure`、`try`、`maybe`、`safe`、`checked`、`validate`、`do`、`handle`、`process` 这类不说明行为的前缀；只做判断的函数用查询名，如 `IsValidPort()`。返回 `Status`/`Result` 已经表达可能失败，`Try` 只用于约定的不阻塞变体（如 `try_lock`）。这条只约束新名字：复用项目已有写法时沿用它的名字，不为符合本规则改名。
- 名称尽量短，上下文由作用域提供：不重复类名、模块名或库前缀，不堆类型、阶段和单位之外的修饰词，作用域越小名称越短；按项目约定用前缀区分符号的 C 代码沿用前缀。不引入 `mgr`、`impl2` 等含混缩写。含义不同的布尔选项用具名枚举或已有 options 类型。

## 验证与交付

交付前逐条复查本次改动：

1. 范围：同一合同下的同族函数、入口和包装层都已检查；公开能力的变化已写进项目文档；改变了已有测试、文档或示例固定的行为时，已记下原行为与新行为。
2. 复用：新增的辅助代码在项目和标准库中都没有等价实现；调用的已有函数，前置条件都已满足；共用函数没有为新功能而改变。
3. 简化：没有为不会出现的情况写的分支、参数或防护机制；单一路径没有抽象；产品代码里没有测试钩子。
4. 检查：同一前提、同一事实、同一输入都只检查一次；没有项目同类接口不做的参数检查。
5. 写法与命名：没有超出项目标准与库范围；资源释放和错误处理沿用项目写法；名称准确表达行为，没有防御式前缀和重复的上下文。

运行改动所需的编译、行为测试和项目要求的检查。项目支持多个编译器（README、CI 或构建文件中有 GCC、Clang、MSVC）时，至少用两种编译；配置了警告选项、`-Werror` 或 clang-tidy 时对改动文件运行，不引入新的诊断；可用的编译器不足时在报告中说明。新增测试覆盖真实回归或合同，不只断言实现细节；简单可逆的修改不强制新建测试。

报告：改变了什么行为、合同覆盖了哪些函数和入口、复用了哪些已有代码、修改了哪些共用函数及原因、关键职责为何这样划分、实际运行了哪些验证、还有哪些限制。下面两项不能省略：

- 失败路径：合同和实现中的每条失败路径（分配失败、长度溢出、I/O 错误、非法输入等）逐条写明是否测试过。测过的写出触发方式，具体到别人能照着复现：用了哪个替换点或替身、构造了什么输入、让哪一步失败，例如“测试文件里的分配器替身让第一次分配返回 NULL”“长度参数传 `SIZE_MAX`”“文件系统替身让第二次 `write` 返回 `ENOSPC`”；只写“注入”“模拟”“已验证”不算写出了触发方式。没测的写出原因，例如项目没有可替换的分配器。
- 已有测试：修改或删除了已有测试断言、或改变了它们固定的行为时，逐条列出原断言、新行为和理由。

被中止、超时或没有执行的检查标为未完成，不写成通过，写好但没有跑完的测试也一样；代码推断不写成实测收益。
