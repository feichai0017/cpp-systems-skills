# 不点名技能的选择案例

本文件定义未点名技能时的选择评估输入与判据，不记录运行结果。显式指定技能的行为测试不能用于证明自动选择正确。

评估时安装技能合集，加载实际全局默认片段，将自然语言任务及最小必要项目材料交给执行者。不要提供预期选择列或显式 `$skill`；从实际读取的 `SKILL.md`、最终修改和工具记录判断，不仅听取自报。将模型/版本、技能提交、提示、加载来源和结果保存在仓库外的运行产物中。

| 自然语言任务 | 初始选择与边界 |
| --- | --- |
| 给这个 C++ 类增加一个已有风格的只读查询方法 | `cpp-core`；不用完整审计或性能流程 |
| 修复 C++ 队列取消后回调仍访问已释放 buffer 的问题 | `cpp-core` + `cpp-lifetime` |
| 精简当前 C++ diff 中重复的检查和纯转发层 | `cpp-core` + `cpp-simplify`；保留安全职责 |
| 审查这个 C++ MR，只报告相对父分支新引入的问题 | `cpp-review`；不自行修改代码 |
| 查明这个 C++ target 的 ASan 测试为何失败 | `cpp-validation`；出现具体寿命问题时补充 `cpp-lifetime`，修代码时补充 `cpp-core` |
| 分析这个 C++ 读路径的 p99 与两次拷贝是否能优化 | `cpp-performance`；改代码时补充 `cpp-core`，不制造实测结果 |
| 将这一行 C++ 注释的 KiB 拼写改对 | `cpp-core` 的轻量部分；不生成并发审计和 benchmark |
| 修复这个 Python 脚本的参数解析 | 不因同目录存在 C++ 文件而加载 cpp 系列 |
| 更新 C++ skill 仓库的安装说明 | 属于技能/文档维护；不仅因出现 C++ 关键词就启动全部 C++ 技能 |

选择可随证据变化；判据是加载是否有任务依据、是否漏掉用户设定的编码底座，以及是否造成无关工作，不能机械要求永远使用固定数量的技能。
