# C++ 生命周期与并发

以真实资源的状态迁移为中心。遵循项目的 owner、同步原语、错误类型及平台合同；不以换智能指针或加一把锁代替因果分析。

## 画出最小生命周期

对本次触及的资源，列出创建者、唯一或共享 owner、借用者、发布方式、最后使用点、回收条件。只覆盖相关资源，不盘点全仓。

当操作跨任务或进程时，补充以下节点：

`申请 → 填充 → 发布 → 获取/校验 → 使用 → 完成 → 解除登记/归还 → 释放`

明确 timeout、cancel、失败、重试和 shutdown 从哪个节点退出，谁负责最终完成与释放。请求超时或逻辑取消不等于设备、网络或回调已停止访问。

## 借用与 RAII

- 检查 view、迭代器、引用和裸指针是否因移动、容器扩容、解映射、替换或异步调度而失效。捕获引用或 `this` 的回调要追到实际调用时刻。
- owner 和 view 同时移动时检查地址关系；默认移动不一定保持内部自引用有效。
- `shared_ptr` 管理共享寿命，不同步 pointee 的读写；`weak_ptr::lock()` 得到的 owner 也不保证协议状态仍可用。
- guard 应覆盖最后一次实际访问。确认释放顺序、成员析构顺序、锁的范围以及提前返回路径。解锁后返回一个 view，通常仍需独立的寿命保护。
- RAII 只覆盖会正常执行析构的路径。进程崩溃、强制终止与跨进程孤儿资源需要协议本身的恢复机制。

## 并发与完成语义

- 每个共享可变字段都要有明确的同步规则，复合不变量需要共同保护。不要把各字段改为 atomic 就宣称状态一致。
- 查清 happens-before 与发布的对象范围；release/acquire 依赖实际匹配的同步关系。引用计数、generation 比较或 relaxed 计数本身不发布对象内容。
- 同步优先沿用项目已验证的锁/队列/执行器。只有当前问题需要时才引入 lock-free；引入时一并给出回收方案及 ABA 处理。
- 检查锁序、条件变量谓词、通知与退出路径；避免在持锁时调用未知回调或执行可能重入的逻辑，除非接口有明确保证。
- 检查成功、失败、取消、超时之间的竞争：终态只产生一次，配额/引用/登记只归还一次，晚到回调可安全处理。
- 重试要明确 operation identity、幂等范围与 ACK 意义；不删除去重、额度或 completion 保护来减少分支。
- 销毁顺序应阻止新任务进入，结束或排空已有访问，再释放被访问资源。等待与取消策略需服从项目的实时性和关闭合同。

## 跨进程与设备

涉及共享内存、RPC、DMA、RDMA 或设备队列时，按需读 [跨边界合同](references/cross-boundary.md)。本地锁、C++ 对象寿命与设备完成是不同保证，逐项说明。

## 有针对性的验证

用可控调度、屏障或假执行器复现关键交错，避免只靠 sleep 或反复重跑碰运气。测试当前改动涉及的失败/取消/释放顺序，不机械枚举所有组合。

竞态检测、地址检测、跨进程重启与真实设备验证分别说明覆盖面。通过一个单进程测试，不能证明跨进程恢复或 DMA 生命周期安全。

交付结论应给出：资源与 owner、触发交错、原来失效的保证、修复后保证成立的位置、实际验证及未覆盖边界。没有具体缺陷时，不强制产生重构建议。
